# 会话标题自动更新（dsh-session-auto-title）

**简体中文** · [English](README.en.md)

根据**整个对话内容**自动重命名 DeepSeek Harness 会话，替换内置的「第一条消息定标题」行为，并带一个设置页可以随时开关和调触发时机。

## 设置页

**设置 → 会话标题**（侧栏左下角「设置」，列表里排在「状态文案」之后）。

| 项 | 作用 |
|---|---|
| 启用自动命名 | 总开关。关掉后不再改写任何标题，已有标题原样保留，也不再产生任何辅助模型请求 |
| 触发时机 | `每条新消息` 或 `每 N 条消息`（N 可填 1–50） |
| 标题仍准确时保持不变 | 关闭后每次触发都会重写标题，哪怕话题没变 |
| 中文标题目标字数 | 2–40，非中文标题按比例换算 |
| 参与命名的消息条数 | 1–60，最早的发言永远保留作为锚点，其余取最近的窗口 |

保存后插件行会重载，从**下一条消息**开始按新设置工作。设置写进 profile 的 `cordis.patch.yml`（`session-auto-title` 那一行），重启后依然有效。

## 行为

- 每来一条新用户消息，标题服务调度一次标题修订；输入是用户在整个会话里说过的话：最早的发言当锚点 + 最近的一段窗口。
- 生成走一次很小的辅助模型请求（默认沿用当前主请求的 provider / model），**不阻塞**正常回复，也不占主对话的 token。
- 标题仍然准确时保持原样，避免因为「继续」「谢谢」这类消息反复改名。
- 手动改过的标题被标题服务固定为 `user` 来源，插件不会再覆盖它。
- 会话很长时先丢弃较早的中间发言、再截断单条消息，保证输入不超预算，而不是整次放弃。

## 配置文件里的字段

设置页只覆盖上面几项；其余通过 `cordis.patch.yml` 的 `config` 调整：

| 字段 | 默认 | 含义 |
|---|---|---|
| `enabled` | `true` | 总开关（设置页） |
| `trigger` | `every-prompt` | `every-prompt` / `every-n`（设置页） |
| `everyNPrompts` | `3` | `every-n` 的 N（设置页） |
| `preserveAccurateTitle` | `true` | 标题仍准确时保持不变（设置页） |
| `targetCjkCharacters` | `12` | 中文标题目标字数（设置页） |
| `maxMessages` | `12` | 送入模型的用户消息条数（设置页） |
| `targetWords` | `6` | 非 CJK 标题的目标词数 |
| `maxInputBytes` | `8192` | 单次标题请求的输入字节上限 |
| `maxOutputTokens` | `64` | 标题请求的输出 token 上限 |
| `timeoutMs` | `45000` | 单次标题请求的超时 |
| `maxCharsPerMessage` | `600` | 单条消息的截断长度 |
| `provider` / `model` | 省略 | 省略时沿用当前主请求的路由；同时填写可独立路由 |

插件不导出 schemastery 的 `Config` schema（profile 安装的是指向工作区的软链接，裸包名 `@deepseek-ai/*` 在那里无法解析），配置由插件自己在激活时校验，非法值会直接让该行激活失败并在日志中报错。

## 限制与差异

- 只有用户消息参与命名；助手回复和工具调用不会进入输入（标题服务只暴露人类文本）。
- 子代理会话同样会被命名，因此子代理的发言也会各触发一次辅助请求；把触发时机改成「每 N 条」可以降低开销。
- 标题最长 80 字节（标题服务的 `maxTitleBytes`），中文约 26 字，超长会被安全截断。
- 与内置 provider 的差异：本插件不写入 `session/title-llm-request` 事件（它记录的是辅助请求的完整原文）。标题本身仍然以 `session/title` 事件落盘，包含所用的消息 seq 和路由。
- 关闭或卸载本插件时 `session-title-llm` 仍是禁用状态，会话会退化为「首条消息的前几个词」这种兜底标题；要恢复内置行为，在 profile 的 `cordis.patch.yml` 里把 `session-title-llm` 重新启用。
